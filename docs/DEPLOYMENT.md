# Luminary — Deployment Guide

This document covers all deployment targets for the Luminary project:
1. **Marketing website** → Vercel
2. **Windows installer (.exe)** → GitHub Releases
3. **Local development** → Electron + Vite

---

## 1. Marketing Website → Vercel

### Auto-Deploy from GitHub (recommended)

1. Push the repo to GitHub
2. In [vercel.com](https://vercel.com) → **Add New Project** → Import your GitHub repo
3. Leave all settings at their defaults — `vercel.json` at repo root auto-configures:
   - Install command: `npm install`
   - Build command: `npm run build --workspace=apps/web`
   - Output directory: `apps/web/dist`
4. Click **Deploy**

> **No manual "Root Directory" setting is needed.** The root-level `vercel.json` handles everything.

### Manual deploy via Vercel CLI

```bash
# Install CLI once
npm i -g vercel

# From repo root — uses root vercel.json automatically
vercel --prod
```

### Update the download URL

After publishing your first `.exe` release to GitHub, update the download link in all four files:

| File | Constant |
|------|----------|
| `apps/web/src/components/Navbar.tsx` | `DOWNLOAD_URL` |
| `apps/web/src/components/Hero.tsx` | `DOWNLOAD_URL` |
| `apps/web/src/components/Pricing.tsx` | `DOWNLOAD_URL` |
| `apps/web/src/components/DownloadSection.tsx` | `DOWNLOAD_URL` |

Replace the placeholder with your actual GitHub release URL:
```
https://github.com/<YOUR_USERNAME>/luminary/releases/download/v2.0.0/Luminary-Setup-2.0.0.exe
```

## 2. Windows Installer (.exe) → GitHub Releases

### Option A: Automated (GitHub Actions — recommended)

Every time you push a version tag, the workflow in `.github/workflows/build-release.yml` automatically:
1. Installs dependencies
2. Generates icons
3. Builds renderer + main process
4. Packages with electron-builder
5. Creates a GitHub Release and uploads the `.exe`

**Steps:**
```bash
# 1. Update the version in package.json
# 2. Commit and tag
git add .
git commit -m "chore: release v2.0.1"
git tag v2.0.1
git push origin main --tags
```

The GitHub Action runs on `windows-latest` and produces a signed NSIS installer.

You can also trigger a manual build from the **Actions** tab in GitHub (select "Build & Release" → "Run workflow").

### Option B: Build locally on Windows

```bash
# 1. Ensure Node.js 20+ is installed
node --version

# 2. Install dependencies
npm install

# 3. Build + package in one command
npm run dist
```

`npm run dist` automatically:
1. Runs `node scripts/generate-icons.cjs` → creates `build/icon.png` + `build/icon.ico`
2. Builds the renderer: `tsc && vite build`
3. Builds the main process: `tsc`
4. Packages with electron-builder into `dist-electron/`

Output: `dist-electron/Luminary-Setup-2.0.0.exe`

### Publish to GitHub Releases manually

```bash
# Set your GitHub token (repo scope required)
$env:GH_TOKEN = "ghp_..."

# Build and publish in one step
npm run dist
```

electron-builder reads the `publish` config in `electron-builder.config.js` and creates/updates a GitHub Release for the current version tag.

### Icon files

Icons are generated by `scripts/generate-icons.cjs` and committed to git:

| File | Purpose |
|------|---------|
| `build/icon.png` | Source icon (512×512, RGBA PNG) — Linux AppImage |
| `build/icon.ico` | Windows installer icon (256×256, ICO with embedded PNG) |
| `build/icon.icns` | macOS bundle icon (placeholder — regenerate on macOS) |

To replace with your custom branded icon:
1. Create a 512×512 `icon.png` with your design
2. Replace `build/icon.png`
3. Run `node scripts/generate-icons.cjs` to regenerate `.ico` and `.icns`
4. Commit the updated files

## 3. Local Development

### Electron app (main + renderer)

```bash
# Start both main process (TypeScript watcher) and renderer (Vite HMR) together
npm run dev
```

The renderer starts on `http://localhost:5173`. Electron loads it automatically.

### Renderer only (browser mode — for UI dev)

```bash
npm run dev:renderer
# Opens at http://localhost:5173
```

> In browser mode, `window.ipc` is undefined. All IPC calls silently fail — the app runs on mock store data only. This is intentional for fast UI iteration.

### Marketing website

```bash
npm run dev:web
# Opens at http://localhost:5174
```

## Versioning

The version displayed in the app, the installer filename, and the GitHub Release all come from the root `package.json` `version` field.

To release a new version:
1. Update `"version"` in root `package.json`
2. Update `DOWNLOAD_URL` constants in the web app if the filename changes
3. Commit → tag → push
